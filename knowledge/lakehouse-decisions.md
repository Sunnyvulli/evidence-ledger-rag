# Decisions and evidence boundaries

1. **Local catalog first.** SQLite-backed Iceberg and local Spark permit a real credential-free run. This verifies format/table behavior, not AWS S3/Glue integration. A cloud implementation needs different catalog/identity configuration.
2. **Typed, bounded actions.** The planner proposes only publish-valid-rows, investigate-drift, or block. Arbitrary SQL, shell execution and model-generated code are not action surfaces. Operator approval must match the proposal hash. The demonstration is deterministic and does not establish learned planning ability.
3. **Model tests before mutation.** Spark stages rows, dbt checks daily uniqueness/non-null/ranges/count reconciliation, then Iceberg commits. A failed model gate must leave the durable table untouched. The dbt candidate is temporary; analytics and catalog commits are not a distributed transaction.
4. **Honest replay.** Compare actual ordered Arrow table contents before skipping a commit. This costs a whole-table read; no streaming or large-scale efficiency claim is made. Multiple concurrent writers are not supported by this wrapper.
5. **Separate row faults from drift.** Domain contracts identify invalid rows. Absolute humidity-mean shifts flag batches for investigation. Seasonal behavior can be legitimate; the threshold is fixed, disclosed, and not an accuracy estimate for real incidents.
6. **No implicit repair authorization.** Airflow can stage/check and request review, but cannot approve. The CLI flag explicitly approves only the local public fixture. Real deployment needs durable operator identity, authorization and replay-safe approvals.
7. **Infrastructure is a boundary, not a cloud credential.** Terraform configuration is only S3/Glue catalog groundwork. Provider validation does not establish an AWS deployment, cost, or service runtime.
